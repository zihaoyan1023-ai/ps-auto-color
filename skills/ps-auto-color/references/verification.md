# 保存与可复现记录

## 文件角色

分别记录源 RAW、工作副本、实际编辑对象（有时是增强 DNG）、当前侧车与最终输出。首次备份核验建立两份一致的初始证据；最终按文件存储形态核验工作对象。源盘卸载时不要宣称又复核了源盘。

遵守主流程中的备份许可与明确例外：已有 XMP／ACR 在续修前保存本轮起点，已存在且核验对应的起点快照可复用，再保存本轮完成后的独立副本。若用户明确禁止任何新备份／新文件，则遵守该限制并记录恢复边界，不另设重复备份关卡。记录放在用户项目的实验目录，不放进技能安装目录。没有相应文件时记录缺失而非伪造空侧车。保留 CR 实际需要的关联数据，尤其是 AI 蒙版／降噪缓存或增强文件；仅复制 XMP 不保证带走全部 AI 数据。

## 导出与参数是两次核对

导出前核对目录、完整文件名、格式、质量、位深、色彩空间、裁切后尺寸、是否缩放及额外锐化。定稿前用 CR 预览比较，避免不断输出中间成片；既有文件冲突时选新名称，只有明确要求才覆盖。

明确普通 SDR 与 HDR 交付。HDR 编辑导出普通 JPEG 时，先在 CR 检查 SDR 预览并按需调整映射，确认保存对话框 HDR Output 未启用；不要拿 HDR 屏幕预览与 SDR JPEG 直接判定“导出变灰”。用户明确要求 HDR 时按其目标保留，不自动降为 SDR。[Adobe SDR 预览与输出](https://helpx.adobe.com/au/camera-raw/using/hdr-output.html)

若导出与 CR 观感不同，先核对同一候选、嵌入 ICC、查看器的色彩管理、HDR／SDR 和缩放条件，再决定是否回到 CR 改图。普通预览不等于已验证社媒上传后的压缩与颜色；除非用户授权并实际测试，不报告“平台显示已通过”。

通过当前 CR 的保存设置／完成操作写入参数，再读取实际文件：

- JPEG：真实可解码、尺寸、ICC、位深及画面正确。质量数值、导出次数来自 UI 记录，不从文件体积反推。
- RAW：源片保持不变；使用侧车存储的工作 RAW 应与基线哈希一致。工作 DNG（包括原生 DNG）可能因合法的内嵌设置更新而改变文件哈希，应记录预期写入与前后哈希，另核验显影及嵌入参数，不能据此判为损坏或无效重试。新增增强 DNG 不与源 RAW 比哈希。若用户明确授权直接编辑源 DNG 且禁止复制，也需披露这种变化，不能宣称源文件字节未变。
- XMP：解析版本、配置文件、全局、裁切、局部调整、增强相关字段；与 UI 记录对应。XML 中保留的值不一定就是 UI 单位。
- ACR 等关联文件：记录存在性与内容哈希，核对与本轮结果对应。哈希不变、mtime 变化或仅文件存在都不足以单独证明成功／失败。
- AI 降噪：UI 完成状态与保留强度、参数字段及所需数据共同核对。字段陌生时保留原始值并标为待确认，不能把普通颜色降噪 25 当作 AI 已启用。

JPEG 脚本只检查其列出的文件属性，不证明 HDR 数据或 HDR 显示正确。其他输出格式使用当前已有、支持该格式的核验工具；HDR 文件信息与相应显示条件分开核验。缺少对应能力时列明未核验项，不因普通 JPEG 检查通过就宣称完整验证，也不自动安装工具。

实测某版本 XMP 的 `LocalExposure2012=0.075` 对应 UI +0.30 EV，其他多数局部滑块按百分之一保存；只能在对应版本与 UI 核对后采用。Glow 共享设置与局部量、裁切坐标与 Orientation 都需分别解释，不做统一倍率／坐标转换。

## 只读辅助脚本

可使用当前可用的 Python 3 运行 `scripts/inspect_photo.py`。不联网、不写输入文件、不启动应用、不显影。RAW／侧车核验仅用标准库；JPEG 解码与 ICC 检查需要已有 Pillow。缺失依赖时标为 incomplete，不自动安装。

脚本检查传入文件本身，不证明某个 XMP 与某张 JPEG 来自同一显影版本。续修后的当前侧车可能已不同于历史成片；对应关系需用本轮保存／导出记录及归档快照核实，不能因几个文件分别可读就宣称版本配对一致。

```sh
python3 scripts/inspect_photo.py --raw /absolute/path/work.ARW --xmp /absolute/path/work.xmp --acr /absolute/path/work.acr --jpeg /absolute/path/result.jpg --expected-raw-sha256 BASELINE_SHA256
```

用实际路径与基线哈希替换示例；从技能目录运行或用脚本绝对路径。只有预期 RAW 文件字节不变时才传入 expected 哈希；允许内嵌设置变化的工作 DNG 分别收集前后记录，不传不相容的断言。输出 JSON 到标准输出：退出 0 表示请求的文件检查通过，1 表示文件／匹配检查失败，2 表示缺依赖或无法完成某检查；**都不代表审美验收**。不传某文件代表没检查该项，不能据此补齐成功记录。`--raw` 单独可用于建立基线；XMP 部分输出原始参数，不自动判断哪些是已完成的 AI 状态。

## 一张照片只保留必要的记录

可按下列内容形成简明 Markdown／JSON，不必为了填表重复工具操作：

```text
输入与输出：源片／工作对象／侧车／成片；哈希及可读性
目标与基线：用户要求；当前版本／配置；参考中可迁移的关系及保留差异
题材与选路：题材／混合题材；光线与表达；所选路线和理由；强化／保留／过头信号
降噪：支持性；启用状态；强度；完成证据；如回退，原因
主要调整：全局关键值；局部作用、覆盖、形状及累计效果
复审循环：看见的问题 → 修改 → 副作用 → 回调 → 再观察；换路时记录原方向失配原因
最终规格：尺寸／ICC／位深／SDR或HDR；质量、缩放及HDR Output来自 UI
参数落盘：已核对哪些字段与关联文件；哪些无法确认
审阅：路线目标与视觉关系；实际检查的区域／缩放／交付状态；独立评审与处理；用户反馈单列
状态：文件已核验／视觉已复核／待用户判断，不混成已满意
```

输出预览可等比例缩放与做色彩管理，比较图可排版和加标签；不要在 CR 外进一步美化它。原尺寸检查与预览检查分别报告。
