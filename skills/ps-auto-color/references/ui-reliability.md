# 原生界面与状态可靠性

## 工具适配

使用环境实际提供的本地桌面控制工具，并阅读该工具当前 API。Codex 中可使用原生应用截图和辅助功能树；其他环境须提供相应能力，不能照搬未存在的调用。不要把会话中的绑定变量、AX 序号、窗口尺寸、截图坐标或快捷键序列当作跨会话固定宏。

优先采用已验证、可观察的原生路径。已有 CR 打开已确认的工作副本就继续；需要打开时可用当前工具支持的文件打开或 Finder 路径。不要为了坚持某一种拖放方式耗费大量失败操作。用户要求操作可见时保持可见。

## 起点迁移

若当前 CR 打开源片，先分清已有侧车与尚未落盘的 UI 调整。有未保存内容时，通过当前 CR 可用的“存储设置”等原生功能保存到本轮工作目录，记录 AI 数据依赖；只有确认快照位置不会写入受保护源文件时才用快照。当前调整与 AI 依赖尚未可靠保存、核验前，不取消或重置。确认可恢复后，可通过已辨认的取消／关闭控件安全退出源文件会话，避免“完成”把设置写回受保护源目录。再通过明确的完整路径打开已核验副本、载入保留设置，核对裁切、全局、蒙版和 AI 状态；仍不将 Escape 当作通用快捷操作。

若当前版本无法把未保存状态及 AI 依赖可靠迁移，保留原窗口并说明具体阻碍，不能悄悄丢弃或把编辑继续写到源目录。用户明确授权直接编辑且禁止复制时，仍优先使用不改 RAW 像素的设置存储方式；源 DNG 可能有内嵌元数据写入，须按该例外范围如实记录。

## 小段执行并核对

1. 看当前应用、窗口、文件名、工具、面板和字段标签。
2. 在同一已确认面板中成组填写相关数值；滑块可精确输入时优先输入，减少反复拖拽。
3. 提交输入、移出文本焦点，等待真实预览更新，核对数值与视觉结果。
4. 切换面板、菜单、窗口、蒙版、缩放或用户介入后，先刷新状态再继续。旧序号可能指向“去杂色”等完全不同的控件。

不能只按辅助功能树的字段顺序猜参数。用标签与截图相互确认；截图不可用、身份不确定、控件禁用时不发送改照片、触发计算或保存的动作。通过已辨认的应用身份进行激活／置前、刷新状态属于允许的恢复操作；恢复后重新确认再调图。

## 去杂色不是展开面板的按钮

“细节”折叠标题与“去杂色”复选框、数量滑块分别识别。进入细节面板不需要点击去杂色。启用前读状态，启用后确认正在处理／已完成，不通过连续点击探测开关。

降噪正在计算时，不为查看别的面板将它关闭；进度与失去前台焦点要区分。无目的开关会浪费计算，有目的的缓存前后比较仍允许。若比较操作会重新计算，优先使用 CR 提供的前后预览或已有结果。

失败时先读取错误及当前状态。可确认的暂时失败在恢复后重试；相同错误连续出现、进度无变化且无法找到恢复条件时停止重复触发，保留状态并说明具体阻碍。不要通过重启整机、清缓存、改 GPU 或安装组件来猜测修复。

进度观察可间隔约 15–30 秒，同一状态连续两次只能说明“暂无可见变化”，不是任务已经挂起的证据；有预计时间时结合它判断，不因估时较长就重启计算。超过估时仍无进展，或没有估时且多次观察无法增加信息时，降低轮询频率并说明状态未能确认；仅在明确错误／可恢复条件下重试。界面长期无法观察且没有安全恢复路径时保留任务、报告受阻，不强制关闭仍可能运行的降噪。

“已完成且可保留”应结合当前版本可观察的证据：去杂色保持选中、数量可读；任务进度结束且预览稳定；必要 AI 更新提示已经处理；保存后设置与关联数据仍对应。界面没有某个标记时不要臆造，改用实际可用的完成提示、参数及重新打开后的状态核对。未能确认必要部分时报告未核验，不仅凭勾选就宣称计算成功。

### AI 更新与版本

Adobe 的 [2025 年 6 月更新](https://helpx.adobe.com/uk/camera-raw/desktop/whats-new/2025-4.html) 已说明增强功能可直接保存在编辑流程中；旧 [Enhance 帮助](https://helpx.adobe.com/camera-raw/desktop/edit-and-enhance-images/sharpening-and-noise/enhance.html) 仍包含技术预览和生成 DNG 的路径。先核对实际版本与界面，不因为读到旧说明就打开技术预览、重复生成增强文件或断言没有 DNG 就未完成。

新图先按输出目标确认 SDR／HDR 编辑模式，再按需要安排：降噪 → 本轮获准且确有需要的修复 → 光学／几何 → 自适应配置（如选用）→ 全局 → 蒙版。它是避免上游变化使下游失效的推荐顺序，既不是强制开启全部工具，也不是续修时从头重做的理由。AI 编辑状态出现更新提示时，先读取具体项目；可单项刷新并查看结果，再处理后续依赖，只有已理解列表并确认范围后才用 Update All。不要每改一个普通滑块就主动重跑 AI。[Adobe AI 编辑状态及顺序，2026-08-27 更新](https://helpx.adobe.com/camera-raw/desktop/ai-and-generative-features/ai-edit-status.html)

## 焦点、失效与安全退出

- 切到 Chrome／Codex 后 CR 曾出现全灰控件、窗口状态失效、`noWindowsAvailable`。先刷新应用状态，尝试正常激活／置前并重新观察；恢复仍失败时请求用户点回 CR，保留已做调整。不要一直用旧坐标重试。
- 临时处理也可能使控件禁用，不能仅凭灰色就认定应用损坏。Creative Cloud 弹窗与 CR 显影功能分别诊断；本技能不含系统修复。
- 文本焦点中按字母可能编辑字段而没有切工具。提交后再用快捷键，随后核对工具。Escape 可能取消整个 CR，不作通用“关闭当前小面板”。
- E／H 等快捷键按当前平台与版本确认；尽量用可见编辑／手形控件。前后比较状态要明确是哪一版本，避免把临时保存的“之前”误当成未处理 RAW。
- 在颜色调整时隐藏蒙版叠加和剪切警告后再判断颜色；需要检查剪切时单独开启并标注，不把警告红蓝色当照片颜色。
- 蒙版列表不可见时先检查工具面板／图钉显示和当前选中对象。可用当前可见图钉或原生菜单；删除时确认名称及区域，只撤销拟删除的调整，不清空全部蒙版。

## 暂停与恢复

用户要求暂停时停止发出新动作，不强制取消正在进行的任务。记录目标文件、当前选中蒙版、已完成参数、降噪进度和是否落盘；区分已在 UI 生效、已写入侧车、已导出。恢复后重新读取状态和挂载情况，不从头重做或假定移动电脑后存储卡仍在。

UI 操作串行；可并行的只读评审／参数检查不争用 Photoshop。节省等待、重复计算和无效点击，不能用省时为理由取消关键复审。
